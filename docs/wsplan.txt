18. MOTION STRATEGY
==================================================

Motion is an enhancement layer, not the foundation.

Do not begin implementation with WebGL.

First make the site fully functional and beautiful without complex animation.

Then add motion.

Motion categories:

REVEAL
Reveal information.

TRANSFORM
Show state changes.

DRAW
Reveal systems or relationships.

DISTORT
Use sparingly for expressive typography.

SCALE
Create emphasis.

TRANSITION
Move between related ideas.

No meaningless:
- bounce
- shake
- random parallax
- endless floating elements
- excessive particle effects
- animation on every heading

Core rule:

NOTHING MOVES WITHOUT A REASON.

Motion should communicate:
- hierarchy
- transformation
- connection
- progress
- discovery
- emphasis

==================================================
19. WEBGL / 3D POLICY
==================================================

Do not use Three.js or WebGL in the initial scaffold.

Build the semantic and visual foundation first.

If WebGL is later introduced:
- use it only for exceptional moments
- lazy-load it
- isolate it from critical rendering
- provide static fallback
- provide reduced-motion fallback
- ensure mobile degradation
- never place core SEO text only inside WebGL

Default:

HTML + CSS + SVG + limited GSAP.

20. PERFORMANCE REQUIREMENTS
==================================================

PERFORMANCE IS A PRIMARY REQUIREMENT FROM DAY ONE.

Do not "optimize later."

--------------------------------------------------
RENDERING
--------------------------------------------------

Use server-rendered/static content wherever possible.

Prefer server components by default if using Next.js App Router.

Use client components only where interaction requires them.

Do not turn the entire page into one client component.

--------------------------------------------------
JAVASCRIPT
--------------------------------------------------

Minimize client-side JavaScript.

Do not load libraries globally unless necessary.

Code-split interactive experiences.

Lazy-load noncritical code.

Do not load heavy animation libraries on pages that do not need them.

--------------------------------------------------
IMAGES
--------------------------------------------------

Use modern formats:
AVIF / WebP.

Use responsive image sizing.

Use explicit dimensions to prevent layout shifts.

Use proper image components.

Lazy-load below-the-fold images when appropriate.

Do not ship original 4K assets if a smaller responsive asset is sufficient.

Do not use huge images as CSS backgrounds when a responsive image element is more appropriate.

--------------------------------------------------
VIDEO
--------------------------------------------------

Do not use autoplay background video as default.

Video must justify its cost.

Use:
- poster image
- compressed format
- lazy loading when possible
- mobile alternative
- reduced-motion alternative

--------------------------------------------------
FONTS
--------------------------------------------------

Load only required font families and weights.

Use font-display appropriately.

Avoid loading unnecessary font variants.

--------------------------------------------------
CSS
--------------------------------------------------

Keep CSS modular.

Avoid giant global style files.

Avoid style duplication.

Use CSS variables/design tokens.

--------------------------------------------------
LAYOUT STABILITY
--------------------------------------------------

Prevent:
- layout shifts
- font shifts
- image jumps
- late DOM insertions
- content jumps caused by JS

--------------------------------------------------
PERFORMANCE GOALS
--------------------------------------------------

Target excellent Core Web Vitals:

LCP <= 2.5s
INP <= 200ms
CLS <= 0.1

Treat these as target thresholds rather than "the site is done once it technically passes."

Measure:
- real mobile performance
- desktop performance
- low-power devices
- slow networks

The site should feel fast.
